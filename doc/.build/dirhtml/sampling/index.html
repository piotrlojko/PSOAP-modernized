Sampling¶

PSOAP provides two sampling entry points:

  • psoap-sample: single-core emcee ensemble sampler

  • psoap-sample-parallel: parallel Metropolis-Hastings sampler with one worker process per wavelength chunk

Both workflows:

  • read config.yaml in the current directory

  • build orbital velocities from psoap.orbit

  • evaluate GP log-likelihood through psoap.covariance

  • write flatchain.npy and lnprob.npy in outdir/runXX/

The parallel sampler uses psoap.samplers.StateSampler for the global proposal loop.

API reference¶

A Metropolis-Hastings sampler for state-ful models within PSOAP.

Replaces the old StateSampler which depended on the deprecated HDF5 backend; chains are now saved as NumPy .npy files.

class psoap.samplers.StateSampler(lnprob, p0, cov, query_lnprob=None, rejectfn=None, acceptfn=None, debug=False, outdir='')[source]¶

Minimal Metropolis-Hastings sampler compatible with the PSOAP sampling workflow.

Parameters:

  • lnprob (callable) – log-probability function.

  • p0 (1D np.array) – starting parameter vector.

  • cov (2D np.array) – proposal covariance matrix.

  • query_lnprob (callable, optional) – called to get the current lnprob from a stateful model (e.g. when sub-process evaluations have modified the state since the last proposal).

  • rejectfn (callable, optional) – called when a proposal is rejected.

  • acceptfn (callable, optional) – called when a proposal is accepted.

  • debug (bool) – enable debug logging.

  • outdir (str) – output directory for saving intermediate chains.
